Design notes
Functionality inventory, preservation matrix, and audit for this redesign.
1. FUNCTIONALITY INVENTORY (confirmed by source documents)
User roles: Player (buyer), Developer/Publisher, Operator (backend-only, no UI). Primary workflows: discovery/browse/search, four acquisition paths, download/install, library management, publishing, campaign management, profile/achievements, settings/diagnostics. Account-scoped: favorites, purchases, claims, library ownership, publishing identity. Desktop-only: filesystem install, install-location settings, native file picker. Empty/loading/error/offline/stale/incompatible/unavailable states are required on every network-backed screen.
2. PRESERVATION MATRIX (old → new)
• Browse/Store front (existing) → Discover ▸ Store home / Browse
• Game detail + buy flow (existing) → Discover ▸ Game details + Payment/Claim/Access modals (new, split out for clarity)
• Library (existing) → Library, tabs expanded: Owned / Installed / Not installed / Updates / Favorites / Access problems
• Publish view (existing, single form) → Publish dashboard + 5-step create wizard + Manage/Releases/Promotions/Activity (relocated & split, no capability removed)
• Account selector / settings scattered across components (existing) → Account menu + Settings (consolidated per inventory's recommendation)
• Social feed (existing) → Community ▸ Social feed, explicitly marked unavailable (matches current truthful-unavailable implementation)
• Favorites — no dedicated screen existed in the source inventory. Modeled as a heart toggle on every game card plus a Library tab, both account-scoped. Flagged as an interpretation, not a removal.
3. RELOCATED / CONSOLIDATED
Purchase receipt and Permanent access record were merged into one "Acquisition history" list with type-specific detail modals, since both are read-only durable-record views differing only in payment-vs-grant provenance. Distribution-provider technical fields (fulfillment keys, attestations) are demoted to a collapsed "Technical details" section everywhere, per the terminology table.
4. FLAGGED AMBIGUITIES (resolved with a stated default)
• Favorites has no source screen — defaulted to card toggle + Library tab (see above).
• "Claim count ... approximate" — shown with an explicit approximation label per the source's instruction, rather than hidden.
• Timed-access badge color is new (this redesign's addition); the source material color-coded paid/public/claim but didn't specify timed — assigned violet to keep all four states visually distinct.
• Access badges (acquisition path) and status chips (ownership/install) were split into two independent semantic labels, never merged — a card or hero can show "PAID" + "OWNED · NOT INSTALLED" simultaneously, but never a Buy action once owned. The mixed home-row heading was renamed from "Claim & Keep — ends in 2d 4h" (falsely implying all four listed acquisition types were a single expiring claim) to "More on the store," a neutral label; "ends in Xd" now only appears on the Timed access and active Claim & Keep badges/promotion panels, which have real deadlines.
5. NOT MODELED / LIGHTER FIDELITY IN THIS PASS
Install-location settings, developer NIP-05 verification flow detail, and per-relay latency testing are represented as static/simplified panels rather than fully wired flows. No community feed content is fabricated, consistent with the source constraint against inventing social activity.
